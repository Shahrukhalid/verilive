# Evaluating the detectors on your own videos

`npm run evaluate` runs Verilive's real engine over a folder of labelled videos and reports how well it separates real from fake: accuracy, precision, recall, a confusion matrix and per-signal statistics. Use it to check a change to a detector, to tune a threshold, or to see how the tool behaves on footage that looks like yours.

It does not weaken the privacy promise. The built app is served from `dist/` on `127.0.0.1`, each video is opened with the same "Analyze a recording" path a person would use, and every other network request is blocked. Videos are read from disk and never uploaded.

## Run it

```sh
npm install
npm run build                      # the script drives the built app in dist/
npm run evaluate -- path/to/dataset
```

Needs Node 22+ and a Chromium that Playwright can start (`npx playwright install chromium`, or set `PW_CHROMIUM_PATH` to a browser binary).

### Folder layout

```
dataset/
  real/   clip-001.mp4  clip-002.webm  ...   (searched recursively)
  fake/   swap-001.mp4  ...
```

Folder names are matched without regard to case. Supported files: `.mp4 .webm .mov .m4v .mkv .ogv` (whatever your Chromium can decode; H.264 needs a Chromium build with proprietary codecs, otherwise convert to WebM first).

### Labels CSV instead

```csv
path,label
clips/a.mp4,real
clips/b.mp4,fake
```

```sh
npm run evaluate -- --labels labels.csv
```

Paths are relative to the CSV file. Labels are `real` or `fake` (`genuine`, `deepfake`, `0` and `1` also work). A header row and `#` comment lines are optional.

### Options

| Option | Default | Meaning |
| --- | --- | --- |
| `--out <file>` | `evaluation-report.json` | JSON report. A per-video CSV is written next to it. |
| `--csv <file>` | next to `--out` | Per-video CSV (path, label, prediction, worst level, score, every signal's suspicion). |
| `--threshold elevated\|high` | `elevated` | Level at which a video counts as "fake". |
| `--flag-at <0..1>` | `0.5` | Suspicion at which one signal counts as a "fake" call, for the per-signal table. |
| `--jobs <n>` | `1` | Videos analysed in parallel. |
| `--timeout <s>` | `900` | Give up on one video after this long. |
| `--limit <n>` | all | Only the first n videos of each label, for a quick trial. |
| `--self-check` | off | Run the three videos in `tests/e2e/fixtures/` and fail unless they are classified correctly. |

## How to read the output

- **One verdict per video.** The worst-rated person decides it. A video is predicted "fake" when that person reaches `--threshold`.
- **"Fake" is the positive class.** Precision is the share of flagged videos that really were fake; recall is the share of fake videos that were flagged; specificity is the share of real videos left alone.
- **Videos without a reading** (no face found, or too short to leave the "collecting" stage) are counted separately and excluded from the matrix. Videos that fail to play are listed with their error. Check these counts before trusting the percentages.
- **Per-signal table.** For each video a signal uses its highest suspicion among people for whom it had at least 0.25 confidence. `measured` is how many videos that covers, `mean real` and `mean fake` are the average suspicion per class, and precision and recall use `--flag-at`. A signal that separates the classes shows a clear gap between the two means.

The analysis runs in real time (a 30 s clip takes about 30 s), so use `--jobs` for big folders and `--limit` to trial.

## Self-check

```sh
npm run build && npm run evaluate -- --self-check
```

Runs the fixtures that already ship with the repo (generated by `scripts/make-fixtures.py` from a public-domain NASA portrait): a simulated 72 bpm pulse labelled `real`, a replayed photo and a pasted face labelled `fake`. It exits non-zero if any is classified wrongly or if the app tries to reach the network. These are synthetic, so passing says the plumbing works, not that the detectors are accurate.

## Using public datasets

Do not commit dataset videos. Each dataset has its own licence and usage terms; many research datasets (for example FaceForensics++, Celeb-DF and the DFDC) are for non-commercial research and need an access request or agreement. Read and follow them, keep the files outside this repository, and cite the dataset in anything you publish.

Tips for meaningful numbers:

- Balance the classes, and include real videos that look like calls: webcams, low light, glasses, compression.
- Use clips of at least 15 seconds with a face in view. The pulse needs about 5 s and the evidence meter about 15 s.
- Report the counts of unrated and failed videos next to accuracy.
- Re-encode a copy of the set at call-like bitrates, since compression is the usual cause of false alarms.
- A few dozen videos give wide error bars. Treat the result as a regression check, not a benchmark.

Verilive gives risk signals, not proof. See [LIMITATIONS.md](LIMITATIONS.md).
